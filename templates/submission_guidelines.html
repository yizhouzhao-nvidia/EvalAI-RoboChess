Linked checkpoint submission

Upload a small .zip containing model links, code references, and instructions for local inference. Host your PyTorch checkpoint on Hugging Face or another service accessible to organizers; you do not need to upload the weights to EvalAI.

Required package contents

  • Model reference: the repository URL, exact immutable revision (for Hugging Face, the full commit hash), and checkpoint filenames or shard index. Pin configuration, tokenizer, preprocessing, and any other required assets as well.
  • Code reference: the GitHub repository URL and full commit hash, or inference code included in the ZIP. Pin any submodules and external dependencies.
  • README: exact model download, environment setup, and inference commands; explain the observation inputs and robot action outputs.
  • Runtime requirements: dependency manifest or a pinned environment reference, Python/PyTorch/CUDA versions, GPU memory requirements, model parameter count, and checkpoint precision.
  • Access and licenses: document access requirements and licenses for the model, code, and assets. Keep the referenced artifacts accessible throughout evaluation.

A moving branch such as main or a mutable tag alone is insufficient. Organizers evaluate the exact revisions recorded in your ZIP. To change the checkpoint or code, make a new submission.

For private or gated models, arrange organizer access before evaluation. Do not include tokens, passwords, or other credentials in the submission.

Submitting to EvalAI

Upload the instructions ZIP through EvalAI's submission interface or use the CLI with the actual challenge and phase IDs:

evalai challenge CHALLENGE_ID phase PHASE_ID submit --file submission.zip --public

See EvalAI CLI instructions for installation and authentication. The example opts into public leaderboard visibility. Use --private if you do not want a public entry; a private submission may need a visibility change before its verified score appears on the leaderboard.

The checkpoint stays on the external model host. The ZIP should contain the references and inference instructions.

Participant-reported scores

Optionally enter success rate (%) and successful/total trial counts in the self-report fields. Explain the evaluation setup. These unverified claims do not affect the official ranking.

Upload does not produce an immediate score. Organizers download the ZIP, fetch the pinned model and code separately, run local trials, and publish verified results afterward.
