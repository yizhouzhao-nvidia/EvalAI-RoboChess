Submission guide

Share the recipe, link the weights.

Submit a small ZIP of model links and runnable instructions. Your PyTorch checkpoint stays on Hugging Face or another host accessible to organizers.

Model scale

Models of approximately 3–32 billion parameters are expected. Include parameter count, precision, and GPU memory requirements so organizers can prepare the runtime.

01 · Model

Pin the exact checkpoint

  • Model repository URL and full immutable revision, such as a Hugging Face commit hash.
  • Checkpoint filenames or shard index, plus pinned configuration, tokenizer, preprocessing, and other required inference assets.
  • License and access requirements. Keep the referenced artifacts accessible throughout evaluation.

A moving branch such as main or a mutable tag alone is insufficient. Arrange organizer access to private or gated models before evaluation.

02 · Code

Make inference reproducible

  • GitHub repository URL and full commit hash, or inference code included in the ZIP.
  • A README with exact download, setup, and inference commands.
  • Observation schema and preprocessing; action schema, units, control frequency, and robot mapping.
  • Pinned dependency manifest or environment reference, Python/PyTorch/CUDA versions, and CPU/GPU memory requirements.

03 · Package

Keep your submission small

submission.zip
└── README.txt
    ├── Model URL + immutable revision
    ├── Code URL + full commit hash
    ├── Download, setup, and inference commands
    ├── Observation and action interfaces
    └── Runtime, license, and access details

You can add dependency files and configuration to the ZIP. Use the example submission README.

Do not include access tokens, passwords, or other credentials. A new model or code revision requires a new submission.

04 · Upload

Submit through EvalAI

Use EvalAI’s submission tab to upload your ZIP, or use the CLI with the actual challenge and phase IDs:

evalai challenge CHALLENGE_ID phase PHASE_ID submit --file submission.zip --public

EvalAI CLI setup and authentication

The example opts into public leaderboard visibility. Use --private if you do not want a public entry; a private submission may need a visibility change before its verified score appears on the leaderboard.

Optional

Include your own results

Add your self-reported success rate (%), successful/total trial counts, and evaluation setup to the optional submission fields. Self-reports do not affect the official ranking.

Organizers fetch the linked model and code separately, evaluate locally, and publish verified results afterward.
